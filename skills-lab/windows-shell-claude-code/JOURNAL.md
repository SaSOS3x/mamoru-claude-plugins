## 2026-10-12 | разработка | Черновик, решения, находки по ходу

- Сначала метод (5 шагов), потом ловушки в формате симптом / причина / что делать, потом проверка и границы; 84 строки против лимита 120.
- Находка 1, дополняет аудит: фикс "PYTHONIOENCODING в settings.json" закрывает только stdout. `open()` без encoding остаётся
  cp1251 (молчаливый мусор при чтении UTF-8). В навык вынесено правило "encoding='utf-8' всегда"; PYTHONUTF8=1 как вариант с оговоркой про cp866.
- Находка 2: PYTHONIOENCODING в проекте только в `.claude/settings.json` этого проекта; в других проектах его нет. Предложение
  пользователю (не делал): добавить `"env": {"PYTHONIOENCODING": "utf-8"}` в `~/.claude/settings.json` либо решить про PYTHONUTF8.
- Находка 3: JAVA_HOME = 17, но java/javac = 21 и javap/jar = 17: три разных JDK в одной сессии. Комментарий в jp.py ("javap 17
  отказывается читать классы Java 21") на тривиальном классе не подтвердился: javap 17 класс 65 прочитал. На реальных классах не проверено.
- Находка 4: `javap` не поддерживает @argfile, `java` поддерживает; значит приём с Class-Path-jar нужен именно javap. Манифест: строки
  не длиннее 72 байт, продолжение с пробела, пути как file:/// URL, папки с "/" на конце: иначе записи молча не читаются.
- Тупики: сначала в env_probe.py осталась лишняя ветка выбора аргументов `-version` (одинаковая в обеих ветках) - убрана.
  Проверять отдельно версию `jar` не стал (путь виден, версия не нужна).
- Скрипты: scripts/env_probe.py (отчёт OK/WARN), scripts/eol.py (CRLF/LF/CR/BOM/MIXED), scripts/classpath_jar.py. Ничего не удалял
  и не менял вне папки навыка и scratchpad.

## 2026-10-13 | исследование | `python -I` и пакеты пользователя (этап v35 порта)

Источник: ошибки агентов этапа v35 (журнал agent-delegation, записи от 2026-10-13). Двое получили ModuleNotFoundError для PIL при
`python -I`, третий снова cp1251. Окружение Claude Code просит `-I` для скачанных и распакованных файлов, а агенты ставили его на
свои скрипты над файлами проекта.
Факт (проверено на этом ПК): Pillow 12.3.0 и openpyxl стоят в `%APPDATA%/Python/Python314/site-packages` (pip --user);
`python -I -X utf8 -c "import PIL"` и `import openpyxl` дают ModuleNotFoundError, `sys.flags.no_user_site` 1, `ignore_environment` 1.
Факт (проверено): `python -P` блокирует подложенный `json.py` в папке скрипта (без флага он импортируется), видит Pillow и
уважает PYTHONIOENCODING. Не принято в навык: окружение прямо требует `-I` для скачанных файлов, и навык не должен учить его
обходить. Для скачанных файлов с пакетом pip решает пользователь.
