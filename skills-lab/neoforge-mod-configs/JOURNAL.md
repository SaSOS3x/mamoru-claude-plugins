## 2026-10-25 | анализ | Блок Distant Horizons из опыта Space Journey

Откуда: разбор общих журналов Space Journey 2026-10-23 по просьбе пользователя (сбор уроков, сводящий агент, проверка
скептиками в workflow wf_6513e25f-1ba). Кандидат S-12, уроки A2-12, A3-13, C-12.
Чего не хватило: в навыке конфигов не было блока DH. В Space Journey DH залил водой пустое измерение (27 010 из 27 671 записей
в базе LOD), пользователь видел синие плиты в двух сборках, на разбор базы DH ушло четыре скрипта. SSAO DH 3.3.2 ломается

Решение: дополнить раздел «Mod specifics», новый навык не нужен: это факты конфига одного мода, общие для любой сборки с DH и
своими измерениями. По решению главной сессии разбора факты DH лежат только здесь, новый навык neoforge-dev-experiments на них
ссылается; в modpack-port-neoforge про SSAO только ссылка сюда.
Скептик: revise. Убрал недоказанное «вступает в силу при следующем старте» (по байткоду DH 3.3.2 своего слежения за файлом нет,
поэтому правило звучит «правь при закрытой игре»), назвал раздел ключа `[client.advanced.graphics.experimental]`, дал версию
в заголовке, добавил число запусков без C1503 (6, по логам игры) и строку паспорта.
Отвергнуто: ничего (кандидат один, вердикт revise).
Проверено: скептиком по байткоду DH 3.3.2, `config/DistantHorizons.toml` и логам игры. Не проверено: другие версии DH;
тест с навыком и без не прогонялся.

## 2026-10-25 | тест | Блок Distant Horizons 3.3.2: синие плиты в пустом измерении, игра запущена

Проверка 2 шага 5 skill-forge (прежний текст : новый), workflow skills-test-sj (wf_279cf530-3e4), 2026-10-25. Исполнители и конструкторы задач - Opus (claude-opus-5-5), судьи - Sonnet (claude-sonnet-5-5), по одному запуску на вариант, два судьи вслепую (X и Y) с обратным порядком вариантов. Gradle и игру исполнители не запускали, судили по файлам и тексту ответа.
Задача T1: «на орбите (измерение мода) Distant Horizons рисует огромные тёмно-синие плиты; убери это, пусть DH там совсем не работает
и не тратит диск; игра сейчас запущена». Пробная папка игры: настоящий DistantHorizons.toml с одной изменённой строкой
(ignoredDimensionCsv = ""), latest.log до момента на орбите без строки проверки, jar DH 3.3.2 только для чтения.
Счёт «прежний : новый»: судья 1 (прежний первым) 6:9, судья 2 (порядок обратный) 7:10. Оба судьи: новый лучше.
Что решило: обе ловушки (обещать, что правка подхватится в запущенной игре; обещать, что DH на орбите не пишет на диск) обошли оба
варианта, и прежний тоже, хотя его раздел File watcher говорит, что изменённый файл читается на ходу: прежний исполнитель сам прочёл
код DH. Различие в двух пунктах: у нового есть копия исходного DistantHorizons.toml с откатом и проверка по строке лога
`DH set to ignore dimensions: [spacejourney:orbit].` вместе с `rendering: no` в F3; у прежнего нет ни копии, ни строки лога.
Вывод по шагу 5: принят, новый не хуже и лучше у обоих судей. Оговорки: задача одна; главная ловушка про перезапуск тест не различил,
перевес дали копия файла и проверка по логу; блок DH даёт ответ почти готовым (конструктор: «новый прямо даёт пункты 2-5»), так что
тест показывает, что текст выполняется, а не что агент нашёл бы это сам. Прежних тестов журнала нет, проверка 3 не нужна.
Не проверено: другие версии DH и остальные блоки «Mod specifics».
