# Задания повторной проверки 2026-10-23

Стенд: `seed/<сценарий>` копируется в `runs/<сценарий>-<вариант>`, у каждого исполнителя своя копия и своя временная папка. Исполнители claude-opus-5-5, один запуск на вариант, запуск инструментом Agent в фоне. Ниже `<run>` - имя копии, `<tmp>` - временная папка исполнителя, `<skills>` - папка навыков плагина agent-workflow.

## Общее начало

```
Рабочая папка: <stand>/runs/<run> (это папка проекта пользователя, работай только в ней). Сегодня 2026-10-23.
Это тестовый стенд: не показывай пользователю карточек и сообщений, не трогай его память и ничего вне рабочей папки. Временные файлы клади в <tmp>. Всё, что хочешь отдать пользователю, оставь файлами в рабочей папке.
```

Для S2 вместо «папка проекта пользователя» написано «папка пользователя».

## Варианты

С навыком:

```
Навыки пользователя лежат в <skills> (папка его плагина agent-workflow). Прочитай skill-forge/SKILL.md целиком и следуй ему; остальные навыки из этой папки читай, если он на них ссылается. ${CLAUDE_SKILL_DIR} в тексте навыка означает папку этого SKILL.md. Инструмент Skill не вызывай: навыки, установленные в самой сессии, к тесту не относятся. Другие папки в <stand>, кроме папки навыков, не читай.
```

Без навыка:

```
Инструмент Skill не вызывай и файлы навыков не читай. Другие папки в <stand> не читай.
```

Сам (проверка, включается ли навык по описанию): о навыках ни слова, только «Другие папки в <stand> не читай.»

## Судьи

`prep_judge.py s1 s2 n1` делает слепые копии: у судьи j1 A - вариант с навыком, у j2 наоборот. Судьи Sonnet, усилие high, каждый в своей папке с `rubric.md`, `seed/`, `A/`, `B/`. Задание судье:

```
Твоя папка: <judge>/<сценарий>-<j1|j2>. Прочитай в ней rubric.md и выполни его. Работай только внутри этой папки, временные файлы клади в её подпапку tmp/. Инструмент Skill не вызывай, сообщений и карточек пользователю не показывай.
Задача, которую получили оба исполнителя: "<задача>"
Критерии: <список>
```

Критерии по сценариям записаны в вердиктах (`verdicts/*.json`, поле criteria). Объективные проверки делает `check.py` (файлы против seed, архив, ключи, вызовы Skill в журналах исполнителей).
