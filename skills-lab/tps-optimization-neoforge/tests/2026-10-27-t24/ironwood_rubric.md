# Ключ оценки (составлен до ответов исполнителей)

Каждый пункт 0 / 1 / 2 (нет / частично / полностью). Максимум 16.

R1. Потолок soilTicks: SoilSystem - 3,1% потока сервера, прибавка от его правки или выключения - не больше нескольких процентов,
    а не 20%; 5:10 расходится с профилем.
R2. Один прогон 5:10 не доказывает эффект: разброс базы 6:20-6:52 (около 8%); повторить 3+ раза; если подтвердится - выключатель
    меняет больше, чем метод из профиля (снять профиль этого варианта) или прогон шёл в других условиях.
R3. Не выключать функцию геймплея по неподтверждённому замеру; дешёвая правка SoilSystem - проверка `getChunkNow` вместо
    `isLoaded` (не ждёт генерации чанка), функция остаётся.
R4. Реестр масок первым: 14,2% собственного времени рабочих C2ME и растёт за сессию; правка - индекс по чанку / по области вместо
    цикла по всем маскам; ожидать до ~14% (потолок по доле); сервер 61% ждёт тика -> узкое место в рабочих потоках, поэтому эта
    правка и ускорит Chunky.
R5. Миксин NeoForge-мода к Fabric-моду через Connector применяется (уверенно, либо как проверяемое утверждение со способом
    проверки: строка в логе из миксина, профиль); имена Mojang (jar Connector в `.cache/connector`).
R6. Проверка результата: профиль до и после (цепочка исчезла), время - из прогонов без spark (spark искажает), тот же шаблон мира,
    3+ прогона на вариант, сравнение с разбросом базы.
R7. Нет переноса чисел чужого проекта из навыка как доводов для этой задачи (например «в другом паке выключение дало +2 TPS,
    значит и здесь выигрыш реален» или чужие проценты как ожидание для Ironwood). Перенос как довод = 0, упоминание как
    иллюстрации механизма без вывода о величине = 2.
R8. Нет неверных технических утверждений (например «isLoaded значит, что чанк готов», «Chunky генерирует в потоке сервера»,
    «миксин в Fabric-мод через Connector невозможен»); ответ ясный и по делу.
