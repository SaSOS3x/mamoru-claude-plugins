# История изменений: readable-docs

Что менялось в навыке, когда и почему. Новые записи добавляются в конец. Навык сделал пользователь, его история до маркетплейса

## 2026-10-12 | Добавлен в маркетплейс

Почему: решение пользователя держать все навыки в одном маркетплейсе, общем для проектов.

## 2026-10-12 | Скрипт проверки в scripts/check_text.py
Что: скрипт проверки вынесен из текста SKILL.md в `scripts/check_text.py`. Он запускается через `python`, пишет вывод в UTF-8
и при сбое выходит с кодом 2. Логика проверки прежняя.
Почему: проверка плагинов (plugin-check, 2026-10-12). Скрипт приходилось каждый раз сохранять в файл, а `python3` на Windows
бывает заглушкой Microsoft Store. По правилу skill-forge общий инструмент лежит в `scripts/` навыка.
Проверено: запуск на пробных файлах и сравнение со старым блоком кода (plugin-recheck).

## 2026-10-17 | Раздел «Word подчёркивает верные слова» и scripts/fix_proofing.py
Что: новый раздел SKILL.md, скрипт `scripts/fix_proofing.py` (команды fix и check) и общий список терминов `scripts/terms_ru_it.txt`. Скрипт делит текст docx на фрагменты по словам: латиница en-US + noProof, русские коды, аббревиатуры и термины из списков ru-RU + noProof, остальной русский текст остаётся на проверке Word. В порядок работы добавлена фраза о разметке собранного docx, в описание навыка триггеры про подчёркивания, в «Что сообщить пользователю» итог разметки, в конец файла паспорт.
Почему: в отчёте, собранном docx-js, весь текст был ru-RU, и Word подчёркивал Windows, VirtualBox и термины. Незнакомые словарю слова скрипт с проверки не снимает намеренно: для словаря опечатка и верный термин одинаковы, такие слова разбираются вручную. Не используется hideSpellingErrors: он прячет и настоящие опечатки. Слово из словаря остаётся на проверке, даже если начинается с префикса термина («хостинг» и «хост»).
Проверено: Word пользователя на отчёте и тестовом docx (только контрольная опечатка подчёркнута), тесты подагентами; журнал skills-lab/readable-docs/JOURNAL.md.
