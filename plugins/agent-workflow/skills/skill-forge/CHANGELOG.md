# История изменений: skill-forge

Что менялось в навыке, когда и почему. Новые записи добавляются в конец. Навык сделал пользователь, его история до маркетплейса
здесь не записана. Журнал правок, сделанных в порте DeceasedCraft, лежит в `_port/skills-lab/agent-delegation/JOURNAL.md`.

## 2026-10-12 | Добавлен в маркетплейс
Что: навык пользователя добавлен в плагин agent-workflow без изменений.
Почему: решение пользователя держать все навыки в одном маркетплейсе, общем для проектов.

## 2026-10-12 | Правило размещения инструментов
Что: шаг 4. Инструмент проекта живёт в проекте, общий в `scripts/` навыка, и навык вызывает скрипт через переменную папки навыка.
Почему: решение пользователя «инструменты только там, где нужны». Две копии eol.py в разных местах уже разошлись.

## 2026-10-12 | Имя переменной словами, точная форма в references/tool-call.md
Что: в тексте шага 4 имя переменной написано словами, а форма вызова вынесена в `references/tool-call.md`.
Почему: проверка плагинов показала, что Claude Code заменяет переменную во всём SKILL.md. Пример в правиле превращался в жёсткий
путь к кэшу с версией, то есть навык учил обратному.
Проверено: в загруженном тексте нет пути вместо имени, Read показывает tool-call.md как есть.

## 2026-10-12 | Где лежит плагин
Что: шаг 4 и таблица в `references/tool-call.md`: кэш в терминале, копия с аккаунта claude.ai во вкладке Code, папка маркетплейса
после `/reload-plugins`.
Почему: после перезапуска приложения навыки пришли не из кэша, а из копий аккаунта. Прежняя фраза «плагин работает из кэша»
была неточной.

## 2026-10-12 | Копия с аккаунта, только если плагин стоит на аккаунте
Что: уточнение в шаге 4 и строка таблицы для плагина, которого нет на аккаунте.
Почему: повторная проверка: пока приложение не скачало копии, вкладка Code брала локальный кэш.

## 2026-10-12 | Среда проекта и CHANGELOG.md
Что: шаг 4 разрешает держать копию общего инструмента в среде проекта, если её учитывает `project_env.py` навыка project-journal.
Паспорт ссылается на CHANGELOG.md. Шаги 6 и 7: с каждой правкой добавляется запись в CHANGELOG.md, а перед правкой его читают.
Почему: два решения пользователя от 2026-10-12. Первое: каждому проекту своя среда со всеми файлами, которые используют агенты.
CLAUDE.md получает каждый агент, а навык нет, поэтому путь в проекте дешевле поиска. Это меняет прежнее правило «проекты не
копируют общий инструмент», но копии теперь учитываются, и расхождение видно сразу. Второе: в каждом навыке журнал изменений,
где главное поле «почему». Правки без причины уже повторялись: проверка сочла недочётом намеренный код 0 у env_probe.py.
Проверено: 27 тестов project_env.py. `claude plugin details` до и после: CHANGELOG.md не меняет цену вызова навыка.
