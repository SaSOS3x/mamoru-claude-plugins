# История изменений: session-error-audit

Что менялось в навыке, когда и почему. Новые записи добавляются в конец. Подробный журнал разработки лежит в репозитории
маркетплейса: `skills-lab/session-error-audit/JOURNAL.md`, база первого аудита рядом в `baseline/2026-10-12/`. До 2026-10-15
он лежал в порте DeceasedCraft (`_port/skills-lab/session-error-audit/`). В плагин он не входит.

## 2026-10-12 | Первый черновик
Что: скрипты scan_fail, classify, show и compare. Они находят все упавшие вызовы в журналах сессии и подагентов, делят их на
настоящие сбои, шум и ожидаемые проверки и сравнивают с прошлым аудитом.
Почему: пользователь строит самообучающуюся систему: каждую ошибку сессии нужно найти, сверить с журналом и решить, нужен ли
навык. Первый аудит (331 упавший вызов) делался вручную.
Проверено: прогон на журналах порта дал 708 строк: 328 настоящих сбоев, 42 ожидаемых, 338 шума.

## 2026-10-12 | Скрипты через переменную папки навыка
Что: все вызовы скриптов идут через переменную папки навыка.
Почему: плагин читается не из папки маркетплейса, а путь к нему зависит от способа установки, поэтому относительный путь ломается.

## 2026-10-12 | Исправления по проверке плагинов
Что: время в `--since` и `--until` разбирается как время. Плохой ввод даёт ERROR и код 2. При 0 вызовов выводится WARNING.
Папка подагентов без основного журнала тоже читается. Пути `/c/...` работают и вне Git Bash. show.py показывает часть
вывода с ошибкой.
Почему: независимая проверка в отдельной сессии (plugin-check, 2026-10-12). Короткая метка времени давала 712 строк вместо 708,
плохой ввод заканчивался Traceback, а мусор в `--since` молча давал «сбоев нет».
Проверено: повторная проверка (plugin-recheck) прогнала каждый случай заново.

## 2026-10-12 | Причина в паспорте записана словами
Что: строка «Изменения» паспорта.
Почему: Claude Code подставляет путь вместо имени переменной во всём SKILL.md, поэтому в паспорте оказался путь к кэшу с версией.
Сама причина «плагин работает из кэша» тоже была неточной.

## 2026-10-12 | Команды через python -I -X utf8
Что: четыре команды запуска.
Почему: повторная проверка заметила, что соседний навык windows-shell-claude-code советует `-X utf8`, потому что `-I` отключает
PYTHONIOENCODING. Вреда не было, скрипты сами переключают вывод на UTF-8, поэтому правка только для единообразия.

## 2026-10-12 | История изменений вынесена из паспорта в этот файл

## 2026-10-15 | Доходит ли CLAUDE.md и ошибки без упавшего вызова
Что: вступление и шаг 3 уточняют, что CLAUDE.md доходит только из папки сессии (Explore и Plan не получают его), и велят сначала
проверить это по записи attachment типа instructions в журнале агента. В шаг 3 добавлен второй источник: ошибки без упавшего
вызова (дневник, отчёты проверяющих, реплики пользователя, в том числе из очереди журнала). Границы говорят о том же.
Почему: аудит Space Journey 2026-10-15. Вступление навыка утверждало, что CLAUDE.md подагент получает гарантированно; в этой
сессии сессия была открыта в папке игры, и CLAUDE.md репозитория не дошёл ни до одного агента. Скрипт отнёс к настоящим 59 сбоев
из 2101 вызова (до ручной проверки), по лишнему вызову каждый, а самые дорогие ошибки сессии (все dev-клиенты без Sodium, неверная проверка снятия
формы Exotic Worlds) упавших вызовов не дали.
Не сделано: правка classify.py (отказ песочницы PowerShell и BUILD FAILED как настоящие сбои). Проверяющий показал, что
предложенное правило ловит все 7 команд PowerShell аудита, и без повторного прогона на периоде DeceasedCraft счёт паспорта
сломается. Скрипты не менялись.
Проверено: формат записи attachment проверен по журналу агента этой сессии; факты сверены проверяющими. Разбор: `_project/skills-lab/a1-2026-10-15.md` и `_project/JOURNAL.md` проекта Space Journey.

## 2026-10-15 | Импорт CLAUDE.md вне папки сессии проверен: нужен флаг пользователя
Что: вместо пометки "способ по документации, делом не проверен" сказано, что импорт файла вне папки сессии загружается только с
флагом hasClaudeMdExternalIncludesApproved у проекта в ~/.claude.json, диалога в приложении нет, флаг ставит пользователь.
Почему: импорт CLAUDE.md из папки игры в проекте Space Journey 2026-10-15 сначала не загрузился. В ~/.claude.json у проекта
hasClaudeMdExternalIncludesApproved false и hasClaudeMdExternalIncludesWarningShown false: приложение Claude диалог разрешения не
показало, и Claude Code молча пропустил импорт (найдено в claude.exe: ClaudeMdExternalIncludesDialog, "Yes, allow external imports").
Пользователь поставил оба флага в true при закрытом приложении, и в новой сессии CLAUDE.md проекта дошёл: запись attachment типа
instructions содержит его (10 815 знаков).

## 2026-10-27 | Исключения Java в выводе с кодом 0
Что: `scan_fail.py` поднимает строки с `Exception in thread` и `Caused by: `; `classify.py` считает такую строку сбоем, только если команда сама запускала java, javac или gradlew (`JAVA_SOFT` и `JAVA_RUN`), иначе это шум (цитата лога). Новая категория `java: uncaught exception in program output` стоит после частных правил (Rhino, пути, Traceback, проверки FAIL, unzip), чтобы не перехватывать их строки; `ClassNotFoundException` и `NoClassDefFoundError` по-прежнему уходят в `java: compile / classpath / bootstrap error`. SKILL.md: шаблон Java в описании сканера, ловушка про Java с `| tail`, числа примера и паспорта.
Почему: аудит вехи T18 проекта Sengoku Jidai World (2026-10-27) не увидел падение офлайн-проверки: `java ... | tail -8` вернул код 0, в выводе был `Caused by: java.lang.ClassNotFoundException`, а `ClassNotFoundException` не совпадает с шаблоном "not found" (слитно). Условие "команда запускала java" - потому что в логах Minecraft строки `Caused by:` повсюду, и чтение лога через grep или sed иначе стало бы сбоем.
Проверено: старые и новые скрипты на одних журналах (папка игры, 620 файлов): период паспорта 709 -> 719 строк, настоящих 329 -> 339, шум 338 без изменений; база Space Journey 2026-10-15 126 -> 138 строк, настоящих 59 -> 64; все журналы (30 366 вызовов) 938 -> 956 настоящих, шума +82 (цитаты логов). Ни одна прежняя строка не сменила категорию и не пропала; все 18 новых настоящих просмотрены глазами - падения Java-программ агентов (NoClassDefFoundError, NullPointerException, ExceptionInInitializerError, ошибки Rhino). Первый вариант с правилом раньше частных перехватил 3 прежние строки (Rhino, путь) - правило перенесено ниже. Исполнителями шаг 5 не тестировался: правка скриптов проверена прогонами, как в записи 2026-10-25. Журнал навыка: записи 2026-10-27.
