# Аудит ошибок сессии

Агенты в одном проекте наступают на одни и те же грабли, потому что урок записан там, куда они не смотрят. Подагент гарантированно
получает только CLAUDE.md (так записано в журнале проекта; env из `.claude/settings.json` на подагентах отдельно не проверено). Журналы, HANDOFF и навыки он читает, только если их назвали в промпте. Аудит
отвечает на три вопроса: что падало (счёт по причинам), записано ли это там, где увидит каждый агент, и что исправить у источника.

Порядок важен. Сначала считаем по журналам сессии скриптом (2 секунды, без токенов), потом сверяем с записями, потом чиним
источник, и только в конце, если ничего другого не помогло, пишем правило или навык.

## Когда запускать

- Раз в этап проекта и после большой задачи или workflow с агентами.
- Когда пользователь просит: "проверь ошибки сессии", "аудит ошибок", "почему агенты повторяют ошибки".
- Когда один и тот же сбой замечен в отчётах агентов второй раз.

Не запускай посреди работы над задачей: аудит читает уже законченные вызовы, а свежий хвост сессии почти весь состоит из
вызовов самого аудита.

## Цикл

### 1. Собрать (scan_fail.py)

```
python -I "${CLAUDE_SKILL_DIR}/scripts/scan_fail.py" --project "<папка проекта>" --out <рабочая папка>
```

`--project` берёт папку проекта и сам находит журналы в `~/.claude/projects/<имя>` (имя = путь, где каждый знак кроме
букв и цифр заменён на `-`; работает с `C:\...`, `C:/...` и Linux-путями). Если не нашёл, дай `--dir` с папкой журналов.
`--session <id>` берёт одну сессию, `--since` / `--until` (UTC, лучше полная метка `2026-10-12T00:00:00Z`; принимаются
также дата `2026-10-12`, `...T23:11Z`, `...+00:00`) режут период; время разбирается как время, а не как текст, мусор вместо
времени останавливает скрипт с кодом 2. Скрипт читает основной
`*.jsonl` каждой сессии и все `<id>/subagents/**/agent-*.jsonl` (включая агентов workflow; папка подагентов, у которой основной
журнал уже удалён, читается как отдельная сессия), сопоставляет каждый вызов с его
результатом и записывает строку, если результат ошибочный (`is_error`), начинается с `Exit code` не 0 или содержит
Traceback, No such file, SyntaxError, denied и подобное. Результат: `rows.json`, `scan_meta.json`. Если найдено 0 вызовов,
скрипт печатает WARNING: это не "сбоев нет", а неверный период, `--session` или `--dir`. Пути вида `/c/...` скрипты на
Windows сами превращают в `C:/...`; неверный ввод (нет папки, плохое время, плохой файл `--rules`) даёт строку `ERROR:` и
код 2, без Traceback.

### 2. Разобрать (classify.py и show.py)

```
python -I "${CLAUDE_SKILL_DIR}/scripts/classify.py" --dir <рабочая папка> [--rules свои_правила.json]
python -I "${CLAUDE_SKILL_DIR}/scripts/show.py" --dir <рабочая папка> --cat "unclassified"
```

Каждая строка получает один из трёх видов. Настоящий сбой делится на жёсткий (код возврата не 0) и мягкий (код 0, но в
выводе Traceback или No such file). Ожидаемое (EXPECTED) - нормальный ответ проверки: grep без совпадений, diff с различиями,
офлайн-тест, который поймал настоящее расхождение. Шум (NOISE) - слово из шаблона в успешном выводе или содержимое прочитанного
файла.

`show.py` показывает в каждой строке часть вывода с ошибкой (строки вокруг последнего маркера ошибки, а не начало), поэтому
команда, которая сначала напечатала файл, а потом упала, видна по ошибке; `--part head` вернёт начало вывода.

После таблицы обязательно посмотри глазами (`show.py --cat ... --n 5`) самый большой кластер, всё в
`unclassified-strong` и по две-три строки из каждого кластера, на который будешь опираться: шаблоны ловят слова, а не смысл.
Для причин, свойственных проекту, добавь свои правила в JSON (`where`: `out`, `cmd` или `tool:Имя`). Нераспознанное, которое
повторяется, получает правило, чтобы в следующем аудите не разбирать его заново.

### 3. Сверить с записями

Для каждого настоящего кластера крупнее двух-трёх случаев ответь на два вопроса. Записано ли это вообще (Grep по CLAUDE.md,
HANDOFF "Facts", журналам навыков, `.claude/skills/*/SKILL.md`)? Доходит ли запись до каждого подагента? Доходят: CLAUDE.md
проекта, `.claude/settings.json` (env, hooks, permissions), сам инструмент (скрипт в проекте, который агент вызывает). Не
доходят: журналы, HANDOFF, навыки, не названные в промпте. Запись вне этого списка считай отсутствующей. Итог - таблица
"ошибка | сколько раз | где записано | доходит до агентов | что чинить".

Это шаг суждения, не подсчёта. Его делает главная сессия или один агент среднего уровня со схемой ответа и списком файлов для
чтения; результат всё равно просмотри сам.

### 4. Исправить источник, потом записать правило

Порядок по пользе, сверху вниз; останавливайся на первом, что убирает ошибку.

1. Убрать причину: переменная окружения в `.claude/settings.json`, установленный модуль, права, hook, маленький инструмент
   вместо угадывания (в проекте DeceasedCraft: `python _port/tools/jp.py <класс>` убрал "class not found" в javap, `eol.py`
   показывает окончания строк по байтам). Меняющее настройки делает пользователь или с его явного согласия.
2. Короткий блок в CLAUDE.md (до 15 строк): правило, число случаев, пример. Только то, что должно дойти до каждого агента.
3. Дополнить существующий навык, если ошибка связана с его областью.
4. Новый навык только по правилам skill-forge: задача повторяется, без подсказки решается плохо, есть проверенный способ. Навык
   про ловушки окружения не создаётся: правило должно доходить до каждого подагента, а навык доходит не всегда.

Ничего из этого не применяй без пользователя: это инструкции для всех следующих сессий. Положи предложения в `skills-lab/`
или покажи списком и жди ответа.

### 5. Записать в журнал

Запись "анализ" в журнал проекта: период, сколько вызовов, сколько настоящих сбоев (жёстких / мягких), топ кластеров, что
решено чинить. Положи `summary.json` и `scan_meta.json` аудита в `audit-baseline/<дата>/` рядом с журналом проекта (не в папку
навыка: в плагине она обновляется вместе с навыком): журналы сессий со временем чистятся, а сравнивать со старым счётом нужно.

### 6. Повторить на следующем этапе и сравнить

```
python -I "${CLAUDE_SKILL_DIR}/scripts/compare.py" --old <папка журнала проекта>/audit-baseline/<дата прошлого аудита> --new <рабочая папка>
```

Печатает по кластерам было / стало, число сбоев на 1000 вызовов, новые и исчезнувшие кластеры. Кластер упал - правка сработала.
Кластер остался - правило не доходит до агентов или чинит не то (вернись к шагу 3). Новый кластер - новый вид ошибки, разбери
его так же. Сравнивай на 1000 вызовов, а не абсолютные числа: объём работы за этап разный.

## Что показал первый аудит (DeceasedCraft, 2026-10-12, пример для ориентира)

Период 8-11 октября 2026, 108 файлов журналов, 8799 вызовов, 708 подозрительных строк. Настоящих 332 по первому аудиту
(138 жёстких + 194 мягких); скрипты навыка на том же периоде дают 328 (138 + 190): 4 мягкие строки - вывод самих скриптов
аудита, теперь это шум. Ожидаемых 42, шума 338. Мягкие сбои - около 58 % настоящих: код возврата цепочки с `;`, `| head`,
`2>&1` или циклом скрывает ошибку, поэтому проверять надо вывод.

| Кластер | Случаев | Причина | Чем исправлено |
|---|---|---|---|
| угаданные пути, glob без совпадений | 114 | агент не знает структуру проекта | отдельно не исправлено: нужна карта путей в CLAUDE.md |
| javap "class not found" | 41 | неполный classpath, угаданное имя | инструмент jp.py |
| кавычки и `\` во встроенном python / heredoc | 50 | Git Bash ломает кавычки и обратный слэш | CLAUDE.md: скрипт файлом через Write |
| ошибка сгенерированного скрипта | 37 | баги в коде, плохой regex, сработавшая защита правки | правилом не исправляется |
| cp1251 в выводе python | 20-23 | кодировка консоли Windows | env PYTHONIOENCODING в settings.json |
| путь `/c/...` в Windows-python | 20 | форма путей Git Bash | CLAUDE.md |
| нет модуля python | 13 | не установлены openpyxl, Pillow | pip install с согласия пользователя |
| JSON / HTTP | 13 | пустой или не JSON ответ | не исправлено |

12 видов не были записаны нигде (оценка агента Sonnet при сверке, не пересчитана). Таблица - состояние на дату, а не метод;
полный список - в журнале проекта, где делался аудит (DeceasedCraft: `_port/skills-lab/agent-delegation/JOURNAL.md`).

## Ловушки самого аудита

- Мягкий сбой не виден по коду возврата. Без разбора текста (шаблоны `SOFT` в classify.py) аудит найдёт только 42 % (138 из 328).
- Аудит ловит собственный вывод: агент, запускающий скрипты аудита, печатает цитаты ошибок (UnicodeEncodeError, Traceback) и
  создаёт ложные строки. Мягкие строки команд, где упомянуты `scan_fail.py`, `rows.json` и т. п., скрипт уже относит к шуму.
  Такие же цитаты дают `cat` / `sed` журналов проекта; их скрипт нарочно не прячет, чтобы не скрыть настоящую ошибку фоновой
  задачи в `cat` её вывода. Смотри их глазами и добавляй правило на команду.
- Искать журналы только в корне папки проекта нельзя: журналы подагентов лежат в `<id сессии>/subagents/**`, и в первом
  проекте DeceasedCraft это 107 файлов из 108.
- Ожидаемое не равно ошибке: `grep` без совпадений тоже даёт код 1. Не добавляй такие строки в счёт и не "чини" их.
- Шаблоны построены под Git Bash / PowerShell на Windows и английские сообщения. Для другой оболочки или языка вывода часть
  строк окажется в `unclassified-strong`: прочитай их и добавь правила.
- Журналы сессий чистятся по настройке Claude Code; старый счёт после чистки не восстановить, поэтому `summary.json` хранится.

## Проверка результата

Таблица в конце `classify.py` сходится: настоящие + ожидаемые + шум = число строк в `rows.json`, `unclassified-strong` равен нулю
или разобран. В каждом кластере, на который опираешься, глазами проверены 2-3 строки. Для повтора аудита на том же периоде:
`--until` с меткой времени из старого `scan_meta.json` (поле `until`, полная форма `2026-10-11T23:11:00Z`), числа совпадают
с точностью до нескольких строк.

## Границы

Навык считает сбои вызовов инструментов. Он не оценивает качество самих навыков (описания, ссылки на файлы, смесь метода с
состоянием проекта): для этого есть проверка по skill-forge, шаг "Сопровождай". Он не заменяет раздел "ошибки по ходу" в отчётах
агентов: тот сообщает причину сразу, аудит видит только то, что упало. Если нужен один сбой, а не сводка, читай журнал сессии
напрямую.
