## 2026-10-15 | Первая версия
Что: порядок поиска на сайтах как у обычного посетителя (работа через страницу, темп, регион через интерфейс, условия
пользователя по карточкам, чтение открытой страницы, итог с доставкой и условием цены, гостевая корзина только для
просмотра), девять ловушек и границы.
Почему: при поиске кровати на маркетплейсах Ozon включил капчу на весь сайт после серии fetch к внутреннему API и прямого
перехода на товар, Авито и Мегамаркет закрыли доступ, а рекомендация по цене выдачи (11 950 ₽) оказалась 16 000 ₽
с доставкой. Пользователь попросил запросы, «менее похожие на автоматические».
Решения, которые не стоит отменять без нового довода:
- Капчу и блок по IP агент не решает и не обходит, а передаёт пользователю: это его IP и его аккаунт, а обход меняет
  правила игры (прокси, платные сервисы).
- Темп «3-5 с после перехода, 1-4 с между действиями» записан как осторожность, а не как доказанная причина. С ним
  капчи не было (в первый такой заход пользователь заодно сменил IP), но и без него в тестах её тоже не было.
- Правило «только через главную» из первого черновика ослаблено до «через страницу, а не мимо неё»: исполнитель без
  навыка открыл прямые ссылки на выдачу Ozon и Яндекс Маркета, и капчи не было. В исходной задаче капча пришла после
  fetch к API и прямого перехода на товар; что из этого её вызвало, не выяснено.
Проверено: 2026-10-15, подагенты Sonnet 5.5 (high) во встроенном браузере, 2 задачи x 2 варианта, по два слепых судьи
с обратным порядком вариантов. Чайник на WB: с навыком 12:7 у обоих судей (без навыка взят фильтр «от 4,7» вместо
«от 4,5»). Робот-пылесос на Ozon и Яндекс Маркете: с навыком 11:10 у обоих. Ключевые числа сверены на сайте вручную.
Из тестов в навык добавлены: фильтр сайта с другим порогом, ref и form_input вместо кликов по координатам, innerText,
когда get_page_text не отдаёт блок, «Входит в заказ» на Ozon, адрес в профиле браузера, цена навыка в границах.
Капчи не было ни в одном прогоне, так что защиту от неё тесты не подтвердили. Потом проверяющий сверил текст
с журналом (78 утверждений, 35 не прошли): общие фразы сужены до наблюдений, непроверенные советы помечены или убраны.
Журнал, записи «тест».

## 2026-10-25 | Корзина, resize и доставка партнёра по первому применению
Что: шаг 8 и «Проверка результата»: сначала посмотреть, что уже лежит в гостевой корзине, удалить только своё, в конце
корзина как в начале. Ловушка 6: resize_window только при мобильной вёрстке. Ловушка 9: служба партнёра на Ozon иногда
показывает сумму доставки сразу.
Почему: первое применение 2026-10-16 (матрас на Ozon, журнал навыка, записи «тест» и «анализ» от этой даты). В гостевой
корзине с начала лежал чужой товар, и правило «корзина пуста» толкало его удалить. При панели около 800 px Ozon уже давал
десктопную вёрстку, а после resize не сработал клик по ref. У Supremo «Курьерской службой партнёра» карточка сразу
показала «+2 000 ₽». Кандидаты 2-5 из той же записи (страница характеристик Ozon, сортировка по цене, Page_Down, scroll_to
перед кликом) не внесены: каждый видели один раз, они ждут теста по шагу 5 skill-forge. Решения записи 2026-10-15 (капча,
темп, «через страницу») не меняются.
Проверено: сверкой с журналом навыка (запись 2026-10-16) и проверкой скептиков workflow wf_6513e25f-1ba (вердикт «revise»,
текст исправлен по журналу). Тест с навыком и без не прогонялся, он будет отдельной записью журнала.
Тест 2026-10-25: не тестировался (нужны живые сайты и согласие пользователя из-за риска капчи); правки проверены только сверкой с журналом и скептиками. Журнал навыка, запись 2026-10-25 «тест».
